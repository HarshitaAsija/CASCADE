# CASCADE map frontend

React hooks, strict TypeScript and MapLibre. Run `npm install` then `npm run dev` from this folder. The default API is `http://localhost:8000`; set `VITE_API_BASE` in `frontend/.env` and restart Vite to override it. Run `npm run build` for the production build.

`src/api/client.ts` fetches `GET /graph/geojson`, `GET /facilities`, `GET /compare`, and `POST /simulate`. The sidebar submits the selected moderate/high/record severity with simulated provenance. A failed HTTP request, malformed payload or five-second timeout uses the corresponding bundled fixture. Failed simulations also show an error and retry button; they explicitly identify the bundled high-flood example so a fallback is never presented as a successful run of another severity. Aborted/unmounted or superseded requests never overwrite newer state. API-sourced data may still be simulated; provenance badges identify that separately.

`src/sample/facilities.json`, `sample_simulation.json` and `sample_comparison.json` are verbatim copies from `data/`. `src/sample/graph.geojson.json` copies `data/sample_graph.geojson`, a snapshot of the current graph stub. Update both copies together. All scenario fixtures are simulated, including named hospital locations and capacity/backup values. No simulation metrics or infrastructure failures are calculated in the frontend.

`App` calls `src/hooks/useSimulation.ts` once and shares the result with `ControlPanel` and `MapView`. Changing severity alone does not execute a request; Run submits it, disables the controls while loading, and updates the map and metric cards when the response arrives. Retry repeats the failed requested severity. The existing backend stub returns the same high-flood fixture for every severity; this limitation is visible in the sidebar.

Baseline vs Intervention displays the selected result from `ComparisonResult.results` beside its own `baseline`. The map switches to that same selected intervention. Saved comparisons are labelled independently of the latest simulation, so a saved high-flood baseline is not misrepresented as a new moderate/record run. Switching back to Simulation restores the latest simulation result. A new run always switches to Simulation mode.

`MetricCards` displays engine-provided values and computes only display deltas (intervention minus baseline). Lower response times, population without access, and degraded counts are improvements; higher evacuation capacity is an improvement. As requested, a green down arrow denotes improvement and a red up arrow worsening; the signed numeric delta retains its actual direction. Evacuation differences use percentage points (pp), not percent change. Null values display an em dash and no numeric delta. Equal values are neutral. Each displayed baseline/intervention value retains its own metrics provenance.

`MapView` maps engine failed/isolated IDs to marker states. The current API has no per-facility degraded IDs. It accepts an optional `facilityStates` mapping to display explicit degraded states when supplied by a caller; it does not infer degradation from capacity, backup availability or flood geometry. Failed and isolated markers are red, functioning markers green, and explicit degraded markers amber. Failed road overlays follow the displayed simulation IDs so an intervention can restore a road independently of the graph fixture's original status.

Facility markers are keyboard-focusable buttons (H hospital, S shelter, F fire station, P power). Click or press Enter/Space for a popup. `ProvenanceBadge` has distinct colours and a tooltip accessible on hover or keyboard focus. Popup values render as React text, not injected HTML.

The basemap uses key-free OpenStreetMap raster tiles and keeps visible contributor attribution. Internet access is required for the basemap; API fallback bundles scenario overlays, not map tiles. No tile prefetching or offline tile cache is implemented. See [OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/) and the [MapLibre raster example](https://maplibre.org/maplibre-gl-js/docs/examples/add-a-raster-tile-source/).

`src/types.ts` is generated from the fixed backend Pydantic contracts; do not edit it by hand.
